Run the extractor on a Windows server

One Windows x64 executable handles setup, scanning, and review. Unattended scans run without a browser or internet connection. Use a browser on the server when you want to review a deck.

1. Prepare the folders

Copy the EXE to a stable folder on the processing machine. Give the account that will run the jobs read and execute access to the EXE, and write access to its temporary directory and the data folder. In PowerShell, set these two paths to your locations.

$exe = 'C:\SlideTools\ConferenceSlideExtractor-Windows-x64.exe'
$data = 'C:\SlideData'
& $exe init-server $data

Setup creates inbox and runs and places a practice ZIP and a copy of this guide in the data folder. Rerunning setup keeps existing batches.

2. Try one batch

Copy-Item "$data\practice.zip" "$data\inbox\practice.part"
Rename-Item "$data\inbox\practice.part" 'practice.zip'
& $exe run-inbox $data
$LASTEXITCODE

Look for Ready for review and exit code 0. Open the printed result folder. The practice run should have two PNGs in selected\slides and two lines of recognized slide text in selected\slides.jsonl, one record per slide. Run the command again with an empty inbox. It should report zero batches.

3. Automate incoming ZIPs

Have the upstream step write each complete session as a uniquely named .part file in inbox, close it, then rename it to .zip in that same folder. The runner takes ownership of each ZIP and retains it under runs\<job>\input. Keeping this original in place lets reviewers open native images later.

In Windows Task Scheduler, select Create Task. Choose the account with access to both paths. To process jobs while signed out, select Run whether user is logged on or not.

Run the task once under the selected account and check Last Run Result. Each invocation processes waiting ZIPs sequentially and exits. Files delivered later wait for the next invocation.

4. Review results and handle exceptions

  • Completed scan. Use runs\<job>\result\manifest.json as the completion signal. Read errors, audit.ocr_errors, stats.needs_review, and stats.review_pairs before using the automatic selection. The scan output is a draft for review.
  • Operator review. Use the result path printed by the runner in the command below. Review flagged slides and export the approved ZIP from the browser. On a remote machine, open the browser in your remote desktop session.
& $exe serve 'C:\SlideData\runs\YOUR-JOB\result' --open
  • Failed job. A nonzero exit code signals a batch or setup failure. Check the console and the job's failed.txt and processing.log. Other queued ZIPs can still finish. After fixing the cause, copy a corrected ZIP into the inbox using the same two-step handoff. The failed attempt stays available.
  • Interrupted run. Start the same runner again. It resumes claimed ZIPs, preserves unfinished results in interrupted-*, and skips completed and already failed jobs.
